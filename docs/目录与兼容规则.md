# 目录与兼容规则

## 分类原则

1. 网关源码进入 `gateway/`；根目录同名 Python 文件只承担旧导入和旧启动命令的兼容，不维护第二份实现。
2. `desktop/`、`extension/chrome/`、`plugins/dsh-step-viewer/` 的源码路径保持不变，避免影响原生控制台、扩展安装源及可能存在的插件源引用。
3. DSH 安装包集中在 `plugins/packages/`，本项目保存的 DSH 补丁在 `plugins/patches/`。整理不代表重新安装这些文件。
4. 工具包分为当前文档、旧文档和上传归档；当前两份文档必须与根目录运行 manifest 的哈希匹配。
5. 文档分为指南、架构、记录和历史归档。旧报告及旧 HTML 预览进入 `artifacts/`。

## 保留的兼容路径

- 根目录 Python 模块：转发到 `gateway`，旧／新导入共享一个模块对象。
- 根目录三个启动 `.cmd` 和依赖清单：旧快捷方式及启动流程不变。
- `extension/chrome/`：浏览器扩展原安装源。
- `desktop/` 与 `plugins/dsh-step-viewer/`：原运行／插件源码位置。
- `tool_reference_manifest.json`：唯一运行清单，不复制第二份清单。
- 根目录 `多账号会话路由说明.md`：旧控制台帮助按钮的文档跳转入口。

## 旧位置如何找

- 根目录其他 Markdown → `docs/` 的对应分类，文件名保留。
- 根目录 `desktop-*.txt/json`、`offline-test-*.txt` → `artifacts/reports/legacy/`。
- 根目录旧 HTML 预览 → `artifacts/previews/legacy/`。
- `plugins/*.tgz` → `plugins/packages/`。
- `patches/` 内补丁 → `plugins/patches/`。
- `工具索引/opus55-tool-catalog-update/` → `tools/reference/current/`。
- `工具索引/` 顶层旧文档 → `tools/reference/legacy/`；ZIP → `tools/packages/`。

## 不动的内容

不删除或迁移 `.console/`、`.venv/`、`logs/`、`.test-tmp/`，不清理浏览器状态、历史草稿或安全备份。不恢复 Git 中既有删除项，不提交、不推送、不改 Git 身份。原有 `analysis/`、`copilot/` 等未参与本次运行链路的历史目录不擅自重构。

旧 `.test-tmp` 验收脚本属于当时的快照；当前统一离线入口为 `scripts/test_offline.py`，会复制新 `gateway/` 源码，但不会复制 `.console/`。原生 UI 与真实模型测试不在默认离线回归中运行。
