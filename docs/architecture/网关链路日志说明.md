# 网关链路日志

## 入口与生效

控制台「诊断与记录」新增「网关请求链路日志」，可刷新及按请求编号前缀筛选，显示当前文件最近150条事件。

先停止DSH请求，再重开控制台和本窗口网关；外部启动的网关需手动重启。只有新版进程才会记录新请求，旧的超时不能补录。扩展内容脚本增加了白名单错误码，重载扩展并刷新实例5页面后生效；未更新扩展时仍有网关日志，但浏览器错误只能记为OTHER。不要在生成中刷新页面。

没有自动重启服务、切换绑定或发送测试消息。

## 文件与保留

- 本项目 `logs/gateway-events.jsonl`，每行一条JSON元数据。
- 达到约2 MiB轮转，最多保留当前文件和`.1`、`.2`、`.3`，总计约8 MiB；适用于默认单网关进程。
- 关闭窗口不清除文件。「本地活动→清空」不会删除链路日志。UI只显示当前文件尾部；较早事件在轮转文件中。
- 日志写入失败不改变请求执行或触发重试；`/health` 的 `logging.write_failures` 给出失败次数，界面显示不完整警告。

## 如何定位

每个Chat Completions请求生成一个随机 `trace`（不是Arena会话ID或账号ID），同一个编号贯穿下列阶段；响应头也包含 `X-Arena-Trace-Id`。`elapsed_ms` 为相对此请求进入网关的单调时钟耗时；`log_seq` 为该请求事件序号。

| 事件 | 含义 |
|---|---|
| request_received | 请求进入网关，包括随后鉴权或参数校验失败的请求 |
| request_prepared | 请求处理已准备好普通响应或流式响应对象；并不代表已经发送消息 |
| http_started | 响应头已交给ASGI传输层；HTTP200本身不是生成成功 |
| queue_enter | 尝试进入对话发送队列，附当时等待数 |
| command_enqueued | 已将命令放入扩展通道 |
| command_taken | 命令被扩展轮询接口取出；不能独立证明Arena接受了发送 |
| first_delta / progress_checkpoint | 网关收到首个真实文本增量；后续约5秒汇总一次 |
| browser_result | 扩展返回结果：成功/完成/不确定标记、文本长度、固定白名单错误码 |
| sse_content | 开始产出可见文本SSE；工具XML仍等待最终校验，不伪装成增量 |
| stream_success / stream_error | SSE内容处理成功，或携带错误结束；错误不伪造成功finish_reason |
| operation_timeout / operation_cancelled | 等待扩展结果超时或被取消，保留既有不确定锁规则 |
| client_disconnected / http_send_failed | 收到客户端断开，或向传输层写入失败 |
| http_finished | ASGI最终响应体发送完成，附字节数/块数及首末增量相对时间；不证明DSH已显示或正确解析 |
| stream_abandoned / http_error | HTTP响应未正常完成或处理异常 |

`delta_count`、`delta_chars` 和 `first_delta_ms`、`last_delta_ms` 可区分“没有文本增量”和“曾有增量后停住”。SSE心跳不是模型文本，也不计入这些文本统计。普通HTTP字节数包括心跳和协议包装，不等于模型正文长度。

不保存请求/回复正文、工具参数或定义、密钥、Cookie、URL、原生会话ID、账号信息和任意异常文本。无法识别的浏览器错误码归为OTHER。原有工具名称审计仍只在内存中，不写入这些文件。

## 本次发现的退出卡点

带真实ASGI响应消费的离线测试复现：`Request.is_disconnected()`内部的取消作用域可能吞掉对监视任务的取消，原代码在清理阶段等待任务退出，导致已准备好的响应无法返回。已增加显式停止标记，并保留ASGI端到端回归测试；没有修改自动重试策略、加长超时或伪造响应来掩盖问题。

这可能解释此前“网关空闲但DSH仍等待”，不等于已证明截图中的请求具有同一原因，现场仍需从新日志核对。

## 正文中的工具标签误判修正

一次现场失败的元数据链路：约15.4秒收到首个文本增量，最终108个增量合计995个UTF-16字符单位；浏览器在约25.7秒返回ok/completed，随后网关最终工具校验返回502。只读核验所绑定实例5的最后回复：长度同为995，唯一的 `<tool_call>` 出现在成对反引号的行内代码中，后面不是JSON，没有实际工具调用块。未采集或记录回复正文、参数及账号信息。

原解析器在全文直接统计标签，错误地把讲解中的字面量当作未闭合调用。本次修正：行内代码和Markdown围栏中的标签只作文本示例；真正位于代码外的调用仍必须有完整JSON、闭合标签、已声明名称和合法参数对象。JSON字符串中的反引号/标签作为参数原样保留，不再次识别为调用。required/selected策略仍不能由示例满足。不会自动补全或执行残缺调用。

原实时流策略仍保守地暂存疑似工具块，最终校验后才返回工具调用；纯讲解场景最终会完整输出被暂存的文本并正常stop，不再因字面量标签报错。不回放失败请求、不自动重发、不自动修改DSH记录。此修正只涉及Python网关，重启网关后生效，无需为此再次重载扩展。

沙盒离线回归161项通过（另33个子测试），包括分块标签正文完整保留、示例不执行、真实未闭合调用仍报错，以及参数中的标签/反引号保真。现场失败原因已通过日志和只读结构核验确认；修正后的DSH现场收发尚未代用户验证。 Windows随后执行同组161项测试通过，4文件哈希回读、编译及git diff检查通过；未重启网关或发送消息。
