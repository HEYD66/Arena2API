# DSH 网页进度通道

## 实现方式

核查安装版 DSH 后，复用它已安装的官方 `llm-pi-ai` 插件及聊天界面的思考区，不新增重复插件、不替换DSH界面，也不继续修改DSH安装库。已核实真实链路：

`当前会话的可信上游事件 → 扩展进度消息 → 网关 reasoning_content → pi-ai thinking_delta → DSH reasoning-delta → 内置思考区`

这不是“只加一个未知字段”：Windows隔离测试已实际加载安装的pi-ai/OpenAI SSE解析器与DSH适配器，确认结束之前就能取得reasoning块，最后才得到一份完整工具调用。前端安装代码的ProcessReasoning组件使用同类reasoning块。未运行真实模型生成或桌面可视化自动化测试。

## 能看到的内容

显示带有 **“Arena网页进度 · 非客户端执行结果”** 标签的状态行，例如：

- 本轮消息已确认提交，等待上游事件。
- 网页正在思考（收到新的思考事件）。
- 网页工具正在接收参数 / 等待返回 / 已返回。
- 正在接收模型回复；工具调用仍待完整校验。
- 网页本轮已结束，等待网关校验。
- 回复已校验；工具调用交给DSH执行。

这些是已观察事件的状态摘要，不是模型内部完整思维链，也不伪造思考文本。不会把上游思考原文、工具参数、输出正文或不透明调用ID传进该通道。合法工具名可以显示；上游网页工具返回不代表Windows本地操作成功。

DSH若折叠了思考/过程区域，需展开查看。不会修改用户的显示偏好。

## 保活与执行安全

- 有效进度成为DSH的真实流式内容块，会推进既有适配器迭代器，重新开始下一次空闲等待。
- 不把SSE注释心跳当成模型活动；上游完全没有事件时不编造进度、不保证无限等待。
- 不完整工具JSON仍受TextGate保护，完整回复校验前不发给客户端执行。活动流和答案流分开；进度不能单独构成成功，也不会污染最终答案前缀校验。
- 延续已有账号、来源、会话、请求ID绑定校验及单调序号去重；旧请求进度不能混入新请求。
- 重复状态最多每5秒更新一次；快速无工具状态限流；浏览器和网关每请求各限256条活动，停止进度后仍保留正常答案接收。
