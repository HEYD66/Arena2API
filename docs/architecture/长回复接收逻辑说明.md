## 不再用累计时长判定失败

此前“网页端10分钟”的说法不准确：这是我们在本地接入扩展中设置的限制，不是已经确认的平台规则。本次不是把10分钟改成30/40分钟，而是移除该终止条件。

| 接收层 | 本次修正 |
|---|---|
| 浏览器扩展 | 删除 `streamTotal` 总截止时间及由它推导的最大连接次数；收到数据、正常60秒接收租期结束、长时间无模型正文均不因累计时长结束任务。 |
| 本项目网关 | `send` 等待实际结果或调用者断开/取消，不再由900秒计时器中断。 |
| 工作台手动发送 | 移除910秒回复等待上限；其他短控制请求不变。 |
| 定向 DSH 适配器 | 原本为本地目标增加的1000000毫秒等待方案被替换。该目标不再仅因转换后的模型内容长期为空而终止；仍保留调用者取消、明确错误与正常结束。 |

DSH 定向修正仅匹配 `opus5.5` + `openai-completions` + `http://127.0.0.1:9090/v1[/]` 或 localhost 同端口/路径；不带URL凭证、查询或片段。其他模型、远端服务及配置文件保持不变。初始HTTP连接处理仍使用原调用参数，没有用Infinity或极大定时器伪装取消上限。

## 中断不再等同于任务失败

- 90秒静默检测现在是**接收连接检查点，不是任务截止时间**。
- 已有可靠 batch 游标时，关闭停滞的接收连接并按原游标只读续收；保留已接收内容及去重状态。
- 尚未消费数据帧时，可以重新建立只读接收连接，不重新提交原消息。
- 已消费数据但没有可安全重放的游标时，静默期间保留**同一个**未完成的读取，不反复创建读取；真正断线则报告结果待核对，不冒充完成。
- 取消“累计3次接收故障就结束”的机制。网络故障采用可取消的退避重连；退避上限只限制重连频率，不限制任务时长或重连总次数。
- 完成仍需匹配本次输入的明确结束边界；认证拒绝、协议错误、会话切换等不会被无限忽略。
- 主动取消、页面/会话切换及调用者断开仍生效。取消本地接收不代表已经停止平台任务，不会自动清除未知结果保护或重新发送。

发起连接、附件上传、短控制请求以及**尚未交付浏览器**的命令仍有各自的网络/交付判定，不是已运行回复的累计截止时间。已有的交付前过期命令现在会明确返回“未执行”，避免网关无期限等待一条从未被交付的命令。

## 没有修改的边界

没有修改终端命令执行时限、工具许可、账号登录、平台验证、来源/会话绑定校验、未完整工具JSON的执行保护或其他插件。运行态只按授权重载本工作台、网关及原实例5/8桥；DSH最终由用户重启。没有解锁、重放任务或发送真实测试提示词。

没有承诺“任何情况都不会中断”：真正断网、页面关闭、授权拒绝、协议变化和用户取消仍需正确处理；此次解决的是自行添加的固定回复截止时间及可恢复接收断线被提前判死的问题。

- Linux 与 Windows 隔离测试：**283项 Python 测试、12个 JavaScript 测试套件**均通过。

- 上述长时间是模拟时钟，不是实际发起了25小时或4小时的模型任务。
