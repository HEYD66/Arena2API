# 多来源会话路由 · 网关0.5.0 / Chrome扩展1.5.0

## 这次改动

发现主体改为各浏览器配置中的Arena2API扩展，不再由主控制台扫描千面实例。每个来源使用独立扩展标识，每条绑定固定“模型别名 → 来源 → 账号ID哈希 → 已有会话”。模型别名只路由，不选择或获取Arena真实模型。

同一来源的会话请求串行，保留各绑定FIFO4/等待60秒和结果不确定锁；不同来源可以独立处理。相同账号的同一会话不能用多个别名/多个来源绕过锁并行发送。别名不能静默改绑，必须显式删除原绑定后再添加目标。

## 首次迁移

1. 先停止DSH请求，关闭旧控制台和旧网关；新版不会强杀外部进程。
2. 在需要接入的浏览器配置中重载新版扩展，刷新Arena页面。扩展新增`scripting`权限，仅用于读取Arena页面的账号资料状态；需要宿主浏览器支持MV3 `chrome.scripting.executeScript` 的MAIN世界执行。
3. 打开新控制台，启动网关。在每个浏览器的Arena页内来源设置中确认本机网关地址，点击“启用接入”按钮；立即保存，无需备注和另点保存。普通浏览器无需千面/CDP。
4. 控制台对明确启用新版插件的来源自动读取首屏已有会话；在账号卡片内搜索或手动加载更多，点击“绑定此会话”，填写模型别名并明确授权客户端发送。旧来源可手动“读取会话”。
5. DSH继续使用同一个本机API地址和API Key，把`model`设置为绑定的别名。若希望不改原来的DSH模型字段，就将第一条别名设为`arena-bound`。

旧 `.console/connection.json` 保留但不自动迁移授权。新绑定保存在本项目 `.console/routes.json`，不覆盖用户旧配置或日志。新路由存在时，未绑定的`arena-bound`不会回退到旧目标。

## 日常使用

- 打开窗口不自动启动网关或发送。已运行新版网关且插件明确启用时，首页会自动只读加载该来源首屏历史；仅兼容桥租约不授权自动历史。每个来源/账号/工作进程组合仅自动尝试一次，不自动翻页或失败重试；来源忙碌、结果不确定或弹窗打开时暂缓。
- 点击“一键启动并恢复已有绑定”，等待已启用来源上线，逐条重新核验原账号和原会话。某个来源离线或换号只使对应恢复失败，不改发到其他来源。
- 也可按绑定单独“核验并恢复”“核对上轮”“停用”“删除绑定”。删除只删除本机路由，不删除Arena会话。
- 网关重启后的绑定默认停用；扩展工作进程重启或账号身份变化也会要求重新核验，不能沿用旧连接直接发送。
- `/v1/models`返回配置的别名。没有任何新来源/路由时保留旧`arena-bound`兼容入口；进入新路由模式后只列配置别名，离线别名调用会明确失败。
- 历史每页50条，搜索只匹配已加载标题，单来源缓存上限5000。自动恢复最多扫描50页/2500条，找不到时手动选择，不猜目标。目前最多32个登记来源、64条绑定，属于资源保护上限，不是实例编号白名单。

## 身份从哪里来

已查看Arena实际前端中的 `SidebarUser -> useUserStore(state => state.user)` 引用。在明确授权的实例5中，只读结构检查找到了侧栏用户对象的 `id / username / email / avatarUrl` 字段；实际适配函数两次读取产生相同的64位十六进制账号哈希。诊断仅输出布尔值/长度，不输出账号值。

扩展在MAIN世界只读侧栏当前React钩子的用户对象，将稳定UUID `id` 经SHA-256转换后返回；用户名仅用于显示，邮件形式的显示名会掩码。原始账号ID、邮箱、Cookie、令牌和密码不被导出。它不读取浏览器账号库，也不调用登录、注册、改密或验证码接口。

**这是已核实当前前端结构的页面状态适配器，不是官方稳定账号API，更不是独立服务端登录认证。** 它依赖侧栏账号组件存在。字段/框架变化、组件未挂载、出现多个身份或退出登录时，来源显示“身份未核验”，禁止历史和发送；可先展开侧栏或刷新页面。每次心跳与命令执行前重读身份，发送目标标签再核对一次，不把用户名当账号ID。

同一账号在多个配置中可被分别发现；来源ID仍区分具体配置。复制浏览器配置可能同时复制扩展ID，此时重叠会话被拒绝。先停止该来源请求，在复制出的页内来源设置中选择“生成新的来源标识”，再重新启用、重新绑定；不会迁移旧授权。

## 千面兼容桥是可选适配器

某些浏览器配置的代理让扩展无法直连本机时，可在“连接设置 → 千面兼容桥”填写明确授权的实例名称及已有CDP端口，勾选保存并授权随“一键启动”启用，再点击“保存并启动此兼容桥”。设置保存在本项目 `.console/bridges.json`；以后只需在首页点击“一键启动”，控制台先启动网关，再启动或复用保存的桥，最后核验恢复原绑定。打开窗口本身不会启动桥。

可保存多个明确目标；列表中的“取消随启动”只撤销以后的启动设置，不中断正在运行的桥或删除会话。桥启动失败不改目标，也不阻断其他已授权来源的恢复。已有外部桥仅在锁、进程、端口、协议和新鲜就绪状态一致时复用，不接管或停止它；冲突状态明确报错。损坏的保存文件不覆盖、不执行。

代码不再限制实例编号；各目标使用独立锁，保留旧实例5锁文件名称用于避免启动重复桥。

兼容桥只定位填写的目标，不遍历读取其他实例的账号内容，不修改千面、代理或浏览器配置，不自动启用CDP。匹配目标不唯一时安全停止。它仍依赖千面现有壳状态和扩展工作进程；其他宿主若需要桥接，需另做该宿主的适配，不能把这个千面桥当成通用浏览器调试桥。

## 日志与保留能力

“请求与日志”可按别名及请求编号筛选。磁盘使用别名派生的短`route_tag`关联，不记录账号、来源名称、会话URL、正文或工具参数。各绑定保留独立工具名称审计。真实文本增量、最终工具校验、Markdown标签误判修复、ASGI退出卡点修复、非流式调用和不确定锁继续保留。

原生`ask_user`等交互的DSH内呈现仍未接通，不自动回答。没有增加自动重试、账号轮换、余额调度或失败转发。连接和恢复只读历史、校验已有快照并定位已有页面，不发送测试消息。

## 异常退出与结果未知保护

发送命令进入队列前，先将该绑定的 `pending_review` 标记持久化并刷新文件；写入失败就禁止发送。确认完整回复或明确未发送的结果后才清除标记。取消、超时、不完整结果，以及保存失败都保留锁。进程退出后重新读取绑定也保留该标记，不因重启、删除或重新绑定而解除。

同一扩展工作进程仍能证明上轮结束时，可通过“核对上轮”清除锁。网关/扩展重启导致证明链丢失的遗留锁会继续阻止该来源恢复，**本版不提供强制解锁或自动重发**；需要人工核实原请求，不应靠删除配置绕过。这是保守拒绝，不是已经实现异常重启后的全自动恢复。

## 控制台0.5.2：网关发送模式，默认正常续聊

用户明确要求默认不带客户端上下文。本项目缺少 `.console/send-mode.json` 时读取为 `normal`，启动和读取设置不创建文件。明确保存时只写此独立文件，不修改API Key、端口、桥或绑定。选项对该项目网关的所有模型别名及旧兼容入口生效，客户端自填`send_mode`不能覆盖网关设置。

### 正常续聊（normal，默认）
- 普通文本请求只发送规范化后的最后一条user内容，不加`user:`前缀、不重发旧用户/助手轮次，也不重发客户端system/developer指令。文本片段按原协议规范化合并。
- 请求以tool结果结束时，保留当前最后一批assistant工具调用的ID、名称、参数及该批全部结果，去掉更早批次和旧助手正文。不简单只截最后一个tool结果，不漏掉并行结果。
- 当前请求的工具定义、工具选择/并发限制、客户端执行工具协议和最终工具校验继续保留。工具协议属于本次必需内容，不等于客户端历史。
- 以assistant/system/developer结尾而无明确新用户消息或完整工具结果批次的普通续聊请求被拒绝，不猜测重发哪条。完整请求仍先经过原有角色、工具配对及大小校验；需要传递完整客户端指令的工作流请选择full。

### 携带客户端上下文（full）
保留原来发送客户端messages及角色信息的行为，含系统/开发者指令、旧用户/助手消息和工具往返；原有工具描述压缩及20万UTF-16发送上限不变。它不获取网页历史，不选择底层模型，不创建会话。

### 生效与边界
- 首次升级需要在无在途请求时停止旧网关并启动新版。网关协议版本仍为0.5.0，新增发送模式能力标记；控制台识别旧进程不支持该能力时阻止一键恢复并提示升级，不把本地保存当作旧进程已生效。
- 新版网关构建发送内容时读取模式，后续请求使用新设置；已排队和正在发送的提示词保持原样。正常/携带上下文两种模式都走原流式、非流式、绑定、授权、串行队列、取消和持久化未知结果保护。
- 原有网页上下文不会因切换而清空。模式选择不是增量去重或重试机制，不自动补发消息。DSH标题辅助请求仍走本地标题处理，不发送到网页。
- 配置损坏或不可读时拒绝发送，不静默退回任意模式。保存失败保留旧文件，支持通过明确保存有效模式修复损坏的模式文件。
