# Arena2API 桌面控制台

> **当前主流程已改为接入已有对话。** 先阅读《当前对话接入说明.md》：扩展提供标签 → 控制台确认绑定 → 手动读取或续聊。无需选择模型。下文模型库/测试实验室是保留的旧接口功能，不是对话接入前置步骤。

日期：2026-10-17。深灰＋蓝色独立桌面窗口，基于 pywebview / Qt WebEngine（PySide6）。

## 快速开始

在解压后的便携包根目录双击 **启动控制台.cmd**。

- 第一次缺依赖时，脚本只在本项目 `.venv` 安装 `requirements-desktop.txt`。
- 渲染运行时随桌面依赖安装到本项目 `.venv`，体积较大，不安装系统级 WebView2 或修改 .NET 策略。
- 这是独立桌面窗口，不是让你在浏览器里打开一个控制台页面；内部界面由项目内 Qt WebEngine 渲染。
- 目前提供源码启动入口，不是已经打包成无需Python的单文件EXE。
- 打开控制台不会自动启动网关、发消息或测试账号。点击“启动网关”后才启动服务。

## 本机兼容模式

经用户确认，正式入口仅在本控制台进程及其子进程内设置 `QTWEBENGINE_DISABLE_SANDBOX=1`，解决本机 Chromium 沙箱启动失败。不会修改系统设置，但本窗口的浏览器进程隔离保护会降低。窗口只加载项目自带界面，不用于浏览外部网站；Arena通过系统浏览器打开。

启动异常详情保存在 `.console/startup-error.txt`；不要把此文件当作活动日志或未经检查公开上传。

## 五个页面

### 工作台
- 一键启动/停止网关，显示本地服务、浏览器扩展心跳和模型数量。
- 显示本地健康检查延迟，不把它当作模型生成延迟。
- 快速打开Arena、扩展目录和使用说明；复制客户端Base URL。
- 扩展“已连接”代表收到心跳，不保证登录态、模型权限或上游接口一定可用。

### 模型库
- 从本地 `/v1/models` 读取列表，搜索、选择默认模型。
- 无凭空添加模型，也不宣传所有列出模型都能调用。
- 默认模型仅影响控制台测试和复制的接入参数，不自动修改DSH。

### 客户端接入
- 设置端口、本地API Key和默认模型。
- 一键复制DSH的OpenAI Chat Completions接入参数；Key可显隐。
- 配置只写入本项目 `.console/config.json`，不会修改DSH、VS Code、浏览器扩展或上游settings.json。
- 修改端口/Key前需停止本窗口启动的网关；改端口后需自行同步浏览器扩展服务器地址。
- 复制的是已保存配置，未保存的输入不会被复制。
- 本地Key是配置文件中的明文，不是凭据保险箱。本版仍限本机使用，不开放公网。

### 测试实验室
- 聊天测试：1次真实模型请求。
- 工具闭环：最多2次真实模型请求，模型调用 `console_echo`，在内存中回显随机字符串，再把工具结果传回并检查回复。
- 点击运行后还需要确认，明确提示可能消耗额度。控制台不会自动开始测试。
- 工具测试不读写文件、不执行终端、不提供通用本机工具执行接口。它验证协议闭环，不等于验证DSH实际执行能力。
- 一次只能有一个控制台测试；测试中禁用重复提交、配置修改和停止服务。
- 测试使用非流式请求，等待期间显示进行中；每次HTTP等待上限180秒，工具闭环最多两轮，因此可能更久。真实流式协议仍由现有网关提供，可通过DSH测试。
- 未实现取消已提交Arena任务的确认协议。关闭窗口或网络断开不代表上游任务停止；结果未知不自动重试。
- 关闭过程中不会在收到第一轮工具调用后自动继续发第二轮。

### 活动日志
- 只保留本窗口最近250条操作及生命周期摘要。
- 不显示原始服务stdout、正文、Cookie、请求头或账号信息；服务日志只翻译白名单中的启动/关闭/端口冲突事件。
- 模型回复只显示在测试结果区，不写入活动日志或文件。关闭窗口后日志不保留。

## 服务所有权与关闭行为

- 控制台只停止由**本窗口**启动的服务进程，不按端口查找后强杀其他程序。
- 端口已有进程时不重复启动；如果是已有Arena2API，可读取状态、复制配置和手动测试，停止按钮禁用。
- 本窗口启动网关时使用项目内Python，绑定 `127.0.0.1`，启用严格浏览器模式，关闭自动改名、推断会话复用、首条提示压缩、正文日志及UI采样。
- 关闭拥有服务或正在测试的窗口会弹出确认。确认后停止自己的进程；DSH中的请求可能中断，Arena中已经提交的任务未必停止。
- 正常退出可清理自有进程；系统强杀窗口、断电等异常退出不承诺完成清理。若下次发现端口占用，会按外部服务处理，不自动接管。

## 文件

- `desktop/app.py`：桌面宿主和固定操作接口。
- `desktop/core.py`：配置、进程、状态和手动测试逻辑。
- `desktop/console.html`：内嵌样式/图标/脚本的界面，无CDN依赖。
- `启动控制台.cmd`：启动入口。
- `requirements-desktop.txt`：桌面依赖。
- `tests/test_desktop_console.py`：纯离线控制逻辑测试。
- `tests/test_desktop_startup.py`：启动门禁离线回归。
- `tests/test_desktop_native.py`：Windows原生渲染和双向桥接自检，最小化窗口自动关闭，不启动网关或发送账号请求。
- `tests/test_desktop_ui.py`：使用模拟桌面桥接的Playwright交互测试（开发用，需额外Playwright环境）。

直接打开 `desktop/console.html` 只会进入**界面预览模式**，不启动服务或发送请求。正常使用请通过桌面启动脚本。

## 验证边界

实现过程在沙箱通过29项控制逻辑测试、35项Chromium界面检查、原有40项OpenAI协议回归。界面检查模拟桌面桥接，阻断HTTP/HTTPS网络；启动、停止、聊天和工具响应均为替身。

本次修复已在Windows通过真实Qt后端初始化、原生测试页面加载和双向JS/Python桥接；另通过5项启动门禁、29项控制逻辑和40项协议回归。35项模拟桥接界面检查也已在沙箱重跑通过。详情见《实施记录-桌面控制台-2026-10-17.md》的后续修复记录。

`--check`现在会初始化真实Qt后端，但不创建窗口。原生加载/桥接自检需单独运行 `.venv\Scripts\python tests\test_desktop_native.py`，结果写入 `.console/native-smoke-result.json`。该自检使用专用测试页面，不等于全部页面或DSH真实流程已验证。

没有在本轮替用户打开真实Arena、启动正式网关或发送模型测试；首次真实接入由用户手动完成。
