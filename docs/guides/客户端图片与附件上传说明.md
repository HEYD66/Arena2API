# 客户端 → Arena 图片与附件链路

## 范围
面向 DSH / OpenAI Chat Completions 客户端，目标始终是明确绑定的已有 Arena 会话。没有新增控制台选文件功能，没有修改 DSH 安装包、密钥或账号绑定。随后按用户要求仅补充了 DSH 的 Arena2API 提供方图片能力默认值。

实现与运行状态：附件版本已经通过官方更新加载到 Arena2API，并完成自有工作台／网关及现有桥接的正常重载。已执行 2 次授权的合成文件真实请求，结果见末节；没有使用私人文件。DSH 应用内模型能力声明仍单独列出，不以临时测试配置冒充应用设置。

## 输入协议
- 图片：`messages[].content[]` 中的 `image_url`，`image_url.url` 必须是 `data:image/png;base64,...` 等内联数据 URL。支持 PNG/JPEG/GIF/WebP。
- 文件：`{"type":"file","file":{"filename":"notes.txt","file_data":"<base64 或带 MIME 的 data URL>"}}`。支持现有上传核心允许的文本/代码、CSV、JSON、XML、HTML、CSS、PDF 等类型；不宣称支持 DOCX/XLSX/ZIP 等未开放格式。
- 用户消息和工具结果均可携带上述内容；系统消息及助手消息不接收附件。
- 不下载远程 URL，不解析 `file://`，不根据路径读取客户端或网关磁盘，不解析其他服务的 `file_id`。客户端必须显式提供文件字节。
- 不把附件 base64 塞进模型提示词；文本中只保留附件名称提示，原字节走上传通道。

## 传输与边界
1. 网关校验类型、文件名、base64、数量及大小，选择本轮消息。
2. 命令只传文件描述与本轮能力令牌。字节留在该活动请求的内存内，通过原来源可读取的分块端点取回。
3. 分块为 256 KiB 的 base64 文本，适配现有本地 CDP 桥约 2.1 MB 的响应上限；不是把附件总大小限制成 256 KiB。
4. 每次取块检查请求、来源、账号/会话绑定和开关；浏览器核对长度及 SHA-256，再交给现有上传核心。
5. 使用现有授权上传地址、PUT 上传和消息挂载流程；上传失败不继续提交消息，不自动重发。
6. 请求结束或取消后，内存附件及令牌随 pending 请求清理；不建立持久文件库。已上传到 Arena 的对象不会自动删除，已发出的消息也不会因此撤回；取消不能被解释为上游一定未执行。

未增加任务总时限。沿用现有上传核心限制：每轮最多 20 个附件，合计 50 MiB；PDF 单文件 10 MiB，其余单文件 25 MiB。普通接口、上传及传输原有超时仍然存在。

## 历史与工具调用
正常模式只传本轮附件，不重传历史附件；完整上下文模式包含所选完整消息中的附件，仍受单次上传额度约束。

已兼容当前安装的 pi-ai 对工具图片生成的确切 `Attached image(s) from tool result:` 包装，保留紧邻的完整工具调用/结果批次，不丢 tool_call_id，也不把其他历史带入正常模式。

不放宽原有原生工具执行域。已验证本轮合成 PNG、TXT、PDF 的实际读取，不代表每一种文档、加密文档或所有模型均已覆盖。原有客户端执行域保护没有放宽。

## 版本兼容
网关要求来源声明 `attachment_protocol=1`，后台分发前还核验目标内容脚本的同一能力标记。旧后台、旧内容脚本或身份不符时拒绝附件发送，不允许静默变成仅文字发送。

DSH 本身还要求所选模型声明 image 输入能力，并使用其现有附件服务。除模拟 HTTP 检查外，本轮还通过实际安装的 DSH 适配器 + 合成附件服务向真实网关发出一次图片请求并成功读取。该测试显式使用内存中的 image 能力声明；此后已单独设置真实 DSH 的 Arena2API 提供方默认输入能力；测试结果仍不冒充当前应用窗口的热加载验证。

### DSH 应用配置边界
修改前只读检查发现，`opus5.5` 模型条目没有显式 `input` 声明，所属配置也没有显式 `defaultInput`。安装的适配器缺省值是 text（若有匹配的模型目录信息，则也会参与推导）。因此不能把测试中显式声明 image 的临时模型，当成 DSH 当前应用配置已经支持选图。

用户随后要求 Arena2API 模型统一自动继承，因此采用提供方级别默认值，而不是逐模型添加或全局修改所有提供方。


## Arena2API 提供方默认图片能力
已在 DSH 当前配置中，唯一指向本机 Arena2API 网关的提供方加入一行：

```yaml
defaultInput: [text, image]
```

- 当前该提供方配置了 1 个模型；以后新增到同一提供方的模型可继承默认声明，无需逐个补写。
- 不自动新增 DSH 模型条目；不修改其他提供方，不覆盖模型自身的明确声明。安装适配器的能力解析优先级仍是模型显式声明、匹配的模型目录能力、提供方默认值。
- 使用新鲜 SHA-256 校验、Windows 当前用户 DPAPI 加密备份、临时文件替换及读回验证。结构比较确认除了这一项以外，配置值完全不变；仅插入 1 行。
- 未修改密钥、模型列表、安装包或插件代码。没有为此重启 DSH，没有再发送测试请求。
- 配置文件已更新，但当前 DSH 窗口是否已热加载该配置尚未确认；不能将磁盘配置验证说成运行中 UI 已验证。

通用 TXT/PDF 等文件的 API 上传能力已经实测；`defaultInput` 声明的是 DSH 的文字/图片模态，不会自动新增 DSH 的通用文档选择入口。
