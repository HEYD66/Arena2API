# 本机对话桥（实例5，不修改千面代理）

## 为什么需要

在当前机器实际复现：本机直连网关 `/health` 返回200；实例5的Arena2API扩展访问同一地址返回502，localhost也相同；经实例5的Mihomo代理端口请求同一路径同样502。

用户明确不允许修改千面配置，因此新增项目内可选桥接程序。它通过用户已开放的本机CDP，仅附加到**实例5的Arena2API扩展后台**，转送该扩展访问本机网关的请求。Arena的会话读取/发送仍使用原浏览器登录和网络路径；不改变千面的代理、出口、账号或其它实例。

## 使用

1. 保持千面、实例5的目标Arena页面和本地网关运行。
2. 双击本项目 **启动本机对话桥.cmd**，保持出现的窗口打开。需要已经安装Node.js 22以上；本机已验证Node 24，不自动安装全局软件。
3. 看到 `READY ... HTTP 200` 后，在Arena2API扩展选择已有对话，点击“提供这个对话”。控制台刷新连接并确认绑定。无需获取模型、凭证或修改千面的代理。
4. 网关重启后需重新绑定；扩展重新加载后，刷新目标Arena页面并重新“提供这个对话”。桥接程序会尝试重新附加同一实例，不会自动选其它实例。
5. 关闭桥接窗口或按Ctrl+C会停止本机转送，不停止网关、不停止或删除Arena任务。

启动脚本默认CDP端口36938、实例名“实例 5”；网关端口从本项目`.console/config.json`读取，缺省9090。CDP端口改变时可在项目内终端显式运行：

```text
node desktop/local_cdp_bridge.cjs --cdp <新的本机CDP端口> --instance "实例 5"
```

不需要千面API Token，不把账号令牌、对话正文或会话地址写入日志。

## 范围与限制

- HTTP白名单只有本机网关的健康检查以及conversation offer/command/result通道；不开放任意URL、任意HTTP管理接口，也不代理Arena请求。
- 使用Node内建HTTP直连127.0.0.1，不经过实例Mihomo。没有新增监听端口或管理HTTP服务。
- 同时核对实例名、当前页与唯一CDP目标、浏览器上下文、Arena2API扩展隔离域和后台身份；遇到歧义停止附加，不猜测目标。
- 不改千面配置。插件内的兼容转送仅在桥接程序持续续约时启用；退出后失效，恢复原有fetch行为。其它扩展和其它实例不注入。
- `.console/local-cdp-bridge.lock`防止重复运行；状态文件仅记录进程、实例标签、就绪与更新时间。它们都在项目内且已被Git忽略。
- 当前定位逻辑使用本机FACET版本现有的运行时实例元信息；千面升级改变结构时可能需要适配，会报等待而不是误连其它实例。
- 桥接建立不等于真实对话协议已验证。Arena权限、待审批工具和上游限制仍按原页面处理。
